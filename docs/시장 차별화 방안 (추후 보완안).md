# 📄 Tardis 프로젝트: 시장 경쟁력 분석 및 미래 확장 전략 (Roadmap)

## 1. 개요 (Overview)

본 문서는 **Tardis (Storage Gateway Proxy)** 시스템이 기존 시장의 유사 도구들과 차별화되는 고유의 경쟁력을 정의하고, 단순한 파일 프록시를 넘어 'AI-Native 인프라'로 진화하기 위한 중장기 확장 전략(Next-Level Differentiators)을 제시합니다.

## 2. 시장 경쟁력 분석 (Competitive Landscape)

현재 글로벌 오픈소스 및 서비스 생태계에서 Tardis와 교집합을 가지는 주요 솔루션들과의 비교 분석입니다.

### 2.1. 기존 솔루션 한계 및 Tardis의 우위

| **비교 대상**                                                    | **주요 특징 및 한계**                                                           | **Tardis의 차별화 포인트 (경쟁력)**                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| **Rclone (`rcd` 모드)**                                        | 70여 개 클라우드를 지원하는 방대한 스위스 아미 나이프.<br><br>  <br><br>비동기 작업을 지원하나 메모리 의존적임. | **SQLite 기반의 완벽한 큐(Queue) 영속성.** 시스템 종료 시에도 작업 유실 없이 대용량 파일 전송 보장.        |
| **최신 AI Gateways**<br><br>  <br><br>_(Kong, Maxim Bifrost)_  | 텍스트(토큰) 트래픽 및 프롬프트 라우팅에 특화됨.<br><br>  <br><br>대용량 I/O 및 콜드 스토리지 처리에 부적합. | LLM 추론이 아닌 **대용량 AI 데이터(모델 가중치, 데이터셋)의 백그라운드 물류(I/O) 전담**에 특화된 니치 마켓 공략.  |

### 2.2. 핵심 포지셔닝

Tardis는 모든 스토리지를 지원하려는 무거운 범용 툴이 아닙니다. "내부 SQLite 큐를 믿고 API 요청 한 번으로 대용량 파일을 Fire-and-Forget(비동기 위임) 할 수 있는 초경량 AI 파이프라인 전용 버퍼"로서 독보적인 입지를 구축합니다.

## 3. 미래 확장 및 개선 전략 (Future Expansions)

Tardis를 단순한 I/O 데몬에서 '지능형 에이전틱 스토리지(Agentic Storage)'로 도약시키기 위한 5가지 핵심 확장 마일스톤입니다.

### Phase 1: 지능화 및 에이전트 연동

**① Vector Storage 통합 (저장 계층의 지능화)**

- **개념:** 단순 파일 저장을 넘어, 텍스트 데이터의 의미(Semantic) 기반 검색 지원.
    
- **구현:** 로컬 큐잉 엔진인 SQLite에 `sqlite-vss` (Vector Search 모듈) 결합. 백그라운드에서 임베딩 API를 호출하여 벡터값을 로컬에 저장.
    
- **효과:** 콜드 스토리지에 보관된 방대한 문서/로그 중 원하는 내용이 담긴 파일만 0.01초 만에 검색하여 핀포인트 다운로드 가능.
    

**② MCP (Model Context Protocol) 규격 적용**

- **개념:** Tardis를 LLM(Claude Code 등)이 직접 제어할 수 있는 공식 '도구(Tool)'로 격상.
    
- **구현:** Tardis 바이너리 내부에 MCP Server 엔드포인트 탑재. (`search_cold_storage`, `request_prefetch` 등 도구 노출)
    
- **효과:** AI 에이전트가 로컬 용량 부족을 인지하면 스스로 과거 모델을 구글 드라이브로 옮기고, 필요한 모델을 미리 다운로드하는 **자율적 인프라 오케스트레이션** 달성.
    

### Phase 2: 데이터 파이프라인 고도화

**③ WASM 기반 미들웨어 (On-the-fly ETL)**

- **개념:** 스토리지 업/다운로드 스트림 중간에서 데이터를 실시간으로 변환하는 핫 스왑 플러그인 생태계.
    
- **구현:** Go 언어의 내장 WebAssembly(WASM) 런타임(예: `wazero`) 활용.
    
- **효과:** 로그 파일의 PII(개인정보) 실시간 마스킹, 혹은 대용량 CSV의 Parquet 실시간 압축 변환 등을 메인 파이프라인 수정 없이 Tardis 단에서 처리.
    

### Phase 3: 스토리지 한계의 궁극적 극복

**④ LRU 기반 가상 무한 스토리지 (Auto-Tiering)**

- **개념:** 로컬 512GB SSD를 5TB 구글 드라이브의 'L1 임시 캐시'처럼 추상화.
    
- **구현:** 파일 접근 이력을 추적하는 LRU(Least Recently Used) 알고리즘 탑재. 로컬 디스크 사용량이 임계치(예: 80%)에 도달하면 오래된 파일부터 자동 백업 후 로컬 삭제(Eviction).
    
- **효과:** 개발자는 로컬 용량을 전혀 신경 쓰지 않고 무한한 5TB 디스크가 장착된 것처럼 파이프라인 개발 가능.
    

**⑤ Zero-Config P2P 캐시 메시 (LAN Sync)**

- **개념:** 동일 네트워크(LAN) 내의 다수 기기(Mac, Windows 등) 간 분산 캐시망 구축.
    
- **구현:** mDNS 기반의 자동 피어 발견(Auto-discovery) 프로토콜 적용.
    
- **효과:** 타 기기에서 구글 드라이브의 특정 파일을 요청할 때, 외부 통신 없이 이미 해당 파일을 다운로드해 둔 로컬 네트워크 내 다른 Tardis에서 기가비트 속도로 직접 당겨옴. 트래픽 및 지연 시간 극단적 단축.
