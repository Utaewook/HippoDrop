# OAuth 리다이렉트 문제 및 재설계 (2026-06-22)

## 1. 개요 및 문제 상황
- **증상**: `hippo init` 시 Google OAuth 인증 후 `http://localhost`로 리다이렉트될 때 "사이트에 연결할 수 없음" 화면이 표시되어 사용자 경험이 크게 저하됨.
- **원인**: Google은 데스크탑 앱 환경을 위해 `http://localhost` 리다이렉트를 권장하며, 이를 위해 로컬 콜백 서버가 수신 대기하고 있어야 하나, HippoDrop은 서버 없이 수동으로 URL을 복사하여 터미널에 붙여넣도록 구현되어 있었음.
- **부가적인 문제**:
  - `fmt.Scan`을 통한 URL 파싱 시, 공백이나 `&` 문자로 인해 URL이 짤리는 버그 존재.
  - PKCE(`code_verifier`, `code_challenge`) 미적용으로 인한 가로채기 취약점.
  - Docker 전용 개발 환경(Headless/원격)에서 로컬호스트 접근 불일치 문제.

## 2. 해결 방안 (의사결정)
사용자와의 `/grill-me` 세션을 통해 다음 사항들을 결정하고 적용함.

### 2.1 지원 환경 및 인증 모드 선택 전략
모든 환경(일반 데스크탑, Docker, SSH 등)을 포괄 지원하기 위해 **자동 감지 + 폴백(Auto & Fallback)** 구조를 채택함.
1. `hippo init` 시 로컬 콜백 서버를 실행.
2. 성공 시 자동 코드 파싱.
3. 로컬 서버 실행 실패 시(또는 사용자가 브라우저를 이용할 수 없는 환경), 수동 복사-붙여넣기 모드로 안전하게 폴백.

### 2.2 로컬 콜백 서버 사양
- **포트 전략**: `127.0.0.1:0`을 사용하여 OS가 임의의 빈 포트를 할당하게 함. (Google Desktop App 정책 상 포트 번호는 무시되므로 안전함).
- **성공 페이지**: 최소한의 평문 메시지("Authentication successful. You may close this window.")를 반환하여 브라우저에 표시. 터미널에는 성공 여부 출력.

### 2.3 UX 및 보안 강화
- **입력 개선**: `bufio.NewReader(os.Stdin).ReadString('\n')`을 도입하여 긴 URL이나 특수문자 파싱 엣지 케이스 해결.
- **PKCE 적용**: Google 권장 사항인 PKCE를 내장 패키지(`crypto/sha256`, `base64`)를 사용하여 구현. `state` 파라미터도 함께 무작위 생성하여 CSRF 방어 체계 보강.
- **기존 토큰 호환성**: 프로젝트가 정식 배포되지 않은 상태이므로 기존 토큰과의 호환성을 고려하지 않음.

## 3. 결과 및 변경 사항
- `cmd/hippo/main.go` 내의 `runInit` 함수에 OAuth 흐름 재설계 내역 전면 적용 완료.
- 사용자(개발자)의 설정 없이도 다양한 환경에서 안정적으로 클라우드 스토리지 접근 권한 획득 가능.
